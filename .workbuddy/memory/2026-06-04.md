## Fix #12 (commit e728898): gendef syntax error

**Problem**: lua-cjson fails to link: `undefined reference to lua_*` for all symbols.
Root cause: `gendef $dll $def` is invalid — gendef only takes the DLL as argument
and writes .def to stdout. The def file was never created, so dlltool was skipped.

**Fix**: Changed to `gendef $dll > $def` (redirect stdout).
Also added: debug output, file existence/size checks, `-m i386:x86-64` for dlltool.

## Fix #13 (commit d60533c): LUA_CORE not defined → no DLL exports

**Problem**: nginx configure finds LuaJIT lib but FFI check fails:
`unsupported LuaJIT build; ngx_http_lua_module requires LuaJIT with FFI enabled.`
DEF file only 94 bytes, dlltool reports "Syntax error in def file ... :1".

**Root cause**: LuaJIT's `luaconf.h` uses `LUA_BUILD_AS_DLL` + `LUA_CORE`/`LUA_LIB`
to control `__declspec(dllexport/dllimport)`. The Makefile defines `LUA_BUILD_AS_DLL`
but NOT `LUA_CORE`, so all `LUA_API` symbols (including `luaopen_ffi`) resolve to
`dllimport` and are NOT exported from `lua51.dll`. `gendef` sees no exports, produces
broken import library.

**Fix attempt**: Added `-DLUA_CORE` to XCFLAGS. Result: no change — DEF still 94 bytes,
FFI still fails. The flag is redundant because every LuaJIT source file already
does `#define LUA_CORE` at the top. The real issue is elsewhere.

## Fix #14 (commit 0114838): use linker-generated import library

**Root cause (revised)**: The `gendef`/`dlltool` approach is fundamentally unreliable
on this MinGW toolchain version. `gendef` consistently produces a 94-byte .def file
regardless of `__declspec(dllexport)` settings. The linker-generated import library
is the authoritative source.

**Fix**: LuaJIT's linker already creates `src/libluajit-5.1.dll.a` via the
`-Wl,--out-implib` flag during the DYNLINK step. Changed `util/configure` msys branch
to copy `src/libluajit-5.1.dll.a` → `luajit-root/liblua51.a` instead of running
gendef/dlltool. The gendef/dlltool path is kept as fallback with a `>128 byte`
minimum DEF size check.

## Fix #16 (commit 7f58a80): Replace --export-all-symbols with objdump PE parsing

**Root cause**: `dlltool --export-all-symbols -D lua51.dll -l liblua51.a` does
NOT work because `--export-all-symbols` treats all symbols in **input object
files** as exports — it doesn't apply when only `-D` (DLL name) is given without
any input objects. The import library was either empty or malformed.

**Fix**: Replaced Method 2 with `objdump -p` approach:
1. `objdump -p lua51.dll` parses PE headers including Export Table
2. Extract symbols from `[Ordinal/Name Pointer] Table` section
3. Build proper `.def` file with `EXPORTS` section
4. Use standard `dlltool -d def -D dll -l target`

This is more reliable because objdump reads the PE structure directly rather
than using gendef's heuristic approach or `--export-all-symbols` (which only
works with object files).

## Fix #17 (commit 2fe8060): Fix objdump regex for bracketed ordinal format

**Root cause**: `objdump -p` outputs the PE `[Ordinal/Name Pointer] Table` as:
```
        [   0] lua_absindex
        [   1] lua_atpanic
```
The regex `/^\s*\d+\s+(\S+)/` couldn't match the bracketed `[N]` format,
resulting in empty .def file → dlltool produces empty import library →
lua-cjson linking fails with undefined references.

**Fix**: Changed regex to `/^\s*\[\s*\d+\]\s+(\S+)/`. Also improved exit
condition: only break on non-empty non-matching lines (allow blank lines).
