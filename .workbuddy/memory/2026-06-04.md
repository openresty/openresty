## OpenResty Windows Build - Fix #10: LuaJIT library detection

**Problem**: CI build still fails at nginx configure step — ngx_lua module can't find LuaJIT library.
Error shows `LUAJIT_LIB=build/luajit-root/luajit/lib` (the "else" / non-msys branch path), meaning `$platform` is not `msys` despite `PATH="/usr/bin:$PATH"`.

**Root cause analysis**: The previous fix (copy `libluajit-5.1.a` → `liblua51.a`) in `util/configure` used Perl `-f` checks which may behave differently across Windows Perl variants. The CI environment's Perl might be reporting `$^O` as something other than `msys` (possibly `cygwin` or `posix`).

**Fix applied** (commit f90e706):
- Added debug output: prints `$^O`, `$platform`, and `ls -la` of LuaJIT lib dir
- Replaced specific `-f` checks with a bash `for` loop glob: `for f in $lib/libluajit*.a $lib/liblua*.a $lib/lua51*.a`
- Copies whatever `.a` file is found to `liblua51.a`
- Warns if no `.a` library is found

**Next step**: Wait for CI run to see debug output. Possible scenarios:
- A) `.a` file exists → copy works → build succeeds
- B) No `.a` file (only `.dll`) → warning → will need to create import library from DLL
- C) Debug output reveals different root cause
